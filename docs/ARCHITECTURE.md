# Архитектура LocalMind OS (предложена по итогам аудита)

Дата: 2026-10-18. Статус: проект, открыт для изменений.

## 1. Позиционирование

LocalMind OS — **интегратор**, а не изобретатель. Система:
- определяет оборудование (AMD GPU в приоритете);
- проверяет совместимость вычислительных стеков (ROCm / Vulkan) по факту,
  а не по таблицам «на глаз»;
- запускает локальные LLM через upstream-движки;
- гарантирует отсутствие скрытого деградирования GPU→CPU.

Всё, что существует в upstream, используется как есть. Собственный код минимален.

## 2. Компоненты и их реальные роли

| Слой | Компонент | Роль | Свой код? |
|---|---|---|---|
| База | Ubuntu LTS + HWE/OEM kernel | платформа, свежий amdgpu | нет |
| Драйвер | amdgpu (ядро), ROCm runtime, Vulkan (Mesa RADV / AMD proprietary) | вычислительные интерфейсы | нет |
| Обнаружение | `localmind-detect` | hw-отчёт: GPU, /dev/kfd, драйвер, VRAM, пути ROCm/Vulkan | **да** |
| Политика | `docs/POLICY.md` + проверка в рантайме | запрет незаметного CPU-fallback; fail-fast | **да (правила)** |
| Матрица | `docs/COMPATIBILITY.md` + фикстуры тестов | доказательства совместимости по моделям GPU | **да (данные)** |
| Движок | llama.cpp (ggml ROCm / Vulkan backend) | основной инференс-движок | нет |
| Convenience | Ollama | простой запуск/раздача моделей поверх llama.cpp | нет |
| Мониторинг | LACT | GUI-мониторинг/оверклок AMD GPU (опционально) | нет |
| CI | Docker/Compose | воспроизводимые сборки и тесты движков | нет |
| Исключено | KVM/QEMU | нет доказанной пользы для MVP | — |
| UI | CLI (`lm`) первичен; GUI вторичен | принципы 6/7 | **да (позже)** |

Обоснование исключения KVM/QEMU: правдоподобная роль — изоляция, но её
закрывает Docker; GPU-passthrough добавляет сложность без доказанной
необходимости. Возврат возможен только под конкретное user story.

## 3. Поток проверки совместимости (ядро идеи)

```
detect → классификация GPU (whitelist/unknown) → probe ROCm → probe Vulkan
      → verdict per-backend: PASS / FAIL / NOT_TESTED
      → выбор движка строго по verdict; ни одного PASS ⇒ явная ошибка,
        НЕ тихий CPU-режим.
```

Ключевое правило: `NOT_TESTED` ≠ `PASS`. Модель может быть заявлена
поддерживаемой только после machine-generated отчёта с реального железа.

## 4. Этапы E0–E9 и критерии готовности (DoD)

- **E0. Правовая база.** LICENSE, README, trademark-дисклеймер, проверка имени.
  DoD: файлы в репо; риск «Ubuntu» снят переименованием. *(частично выполнено)*
- **E1. hw-detector v0.** read-only JSON-отчёт о GPU/драйвере/устройствах.
  DoD: unit-тесты на фикстурах; запуск ничего не меняет в системе.
- **E2. Тестовый стенд + golden-фикстуры.** Реальное Radeon-железо или аренда.
  DoD: ≥1 отчёт с реальной RX 6xxx/7xxx сохранён и проходит схему.
- **E3. ROCm probe.** /dev/kfd, rocminfo/hip, версия, видимая VRAM.
  DoD: корректный verdict PASS/FAIL на стенде; FAIL не блокирует Vulkan-путь.
- **E4. Vulkan probe.** vulkaninfo, нужные расширения (напр. VK_KHR_cooperative_matrix).
  DoD: аналогично E3.
- **E5. llama.cpp.** Сборка ggml-ROCm и ggml-Vulkan в Docker; smoke-тест
  tiny-модели, замеры ток/с.
  DoD: воспроизводимый `make bench`; результаты — в COMPATIBILITY.
- **E6. Ollama-адаптер.** Проверка, что Ollama реально использует GPU
  (rocmsmi/utilization), а не CPU.
  DoD: тест «GPU busy во время генерации».
- **E7. health-check + policy-enforcer.** `lm doctor`; детектирование попытки
  fallback и явный отказ.
  DoD: интеграционный тест имитирует исчезновение /dev/kfd → система
  останавливается с ошибкой, а не переходит на CPU.
- **E8. CLI `lm`.** detect/doctor/run/status — полный паритет с GUI.
  DoD: все операции доступны из CLI; man-страницы.
- **E9. GUI.** Только поверх стабилизировавшегося CLI.
  DoD: GUI не имеет эксклюзивных функций.

## 5. Открытые вопросы

1. Целевые GPU: RDNA2+ только через Vulkan, или также отдельные SKU через
   ROCm (официальный список поддержки Radeon в ROCm узок)?
2. Формат поставки: ISO-образ, метаданные-оверлей поверх чистой Ubuntu,
   или скрипт-бутстрап? Влияет на E0–E1.
3. Источник тестового железа для E2 — без него заявления о совместимости
   невозможны (принцип 4).
4. Лицензионные условия дистрибуции бинарных моделей (Ollama registry).
5. Юридическая проверка имени «LocalMind» (домен, товарные знаки).
